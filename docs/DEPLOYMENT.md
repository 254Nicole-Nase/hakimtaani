# Deploying HakiMtaani

HakiMtaani is TanStack Start (Vite + Nitro). The same code builds for Lovable, Vercel, or any Nitro target; only the preset and environment variables change.

## Environment variables

| Variable | Scope | Notes |
|---|---|---|
| `VITE_SUPABASE_URL` | build + browser | Supabase project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | build + browser | Publishable (anon) key |
| `SUPABASE_URL` | server | Same project URL |
| `SUPABASE_PUBLISHABLE_KEY` | server | Same publishable key |
| `GOOGLE_API_KEY` | server, secret | Gemini, used for AI when not on Lovable |
| `GOOGLE_AI_MODEL` | server | Optional; defaults to `gemini-3.7-flash` |
| `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT_NAME` | server, secret | Takes priority over Gemini when set |
| `AZURE_DOCUMENT_INTELLIGENCE_ENDPOINT`, `AZURE_DOCUMENT_INTELLIGENCE_KEY` | server, secret | Optional: read uploaded PDFs/photos |
| `AZURE_SPEECH_REGION`, `AZURE_SPEECH_KEY` | server, secret | Optional: voice input (otherwise Gemini transcribes) |
| `LOVABLE_API_KEY` | server, secret | Set automatically inside Lovable; does not work elsewhere |

The `VITE_*` pair is inlined at build time, so it must be set for the build, not only at runtime.

**AI provider order:** Azure OpenAI → Google Gemini → Lovable AI Gateway. The first one configured is used.

## Vercel

`vercel.json` is committed. It installs with bun, builds with `NITRO_PRESET=vercel`, and serves `.vercel/output`.

1. In Vercel, **Add New → Project** and import `254Nicole-Nase/hakimtaani`.
2. Under **Environment Variables**, add the four Supabase variables and `GOOGLE_API_KEY` (get one free at https://aistudio.google.com/apikey). Add them for Production and Preview.
3. Deploy. Every push to `main` then redeploys, and each pull request gets its own preview URL.

Local check: `npm run build:vercel`.

## Lovable

Nothing to configure. Lovable sets the Supabase variables and `LOVABLE_API_KEY` itself. Use **Publish** in the editor.

## CI

`.github/workflows/ci.yml` runs typecheck, unit tests and a Vercel build on every push to `main` and every pull request. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` as GitHub Actions repository secrets so the build matches production.

Lint is not yet part of CI: the code generated by Lovable has formatting errors throughout. Run `npm run lint -- --fix` once, then add a lint step.
